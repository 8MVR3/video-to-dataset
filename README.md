# Видео → кадры для разметки

Скрипт готовит видео к разметке объектов: нарезает кадры с заданным шагом, выкидывает почти одинаковые, делит данные на train и val и раскладывает кадры по архивам для разметчиков. Одна команда вместо ручной возни с плеером и папками.

## Зачем деление по видео

Самая частая и незаметная ошибка при подготовке датасета из видео — делить на train и val по отдельным кадрам. Тогда соседние, почти одинаковые кадры одного ролика попадают в обе выборки, модель на проверке видит то, на чём училась, и метрики выходят завышенными. Здесь целые видео уходят либо в train, либо в val, поэтому пересечений нет.

## Что делает

- Берёт кадр каждые N секунд, по желанию только из заданного отрезка видео.
- Сравнивает кадр с предыдущим оставленным по перцептивному хэшу (dHash) и выбрасывает почти одинаковые: при статичной камере это экономит разметчикам часы.
- Делит данные на train и val примерно в нужной пропорции. Видео делятся целиком, поэтому чем их больше, тем точнее доли.
- Собирает архивы по N кадров и распределяет их между разметчиками по кругу. Кадры одного видео держит рядом: так разметчику проще.
- Сохраняет `manifest.csv` (какой кадр из какого видео, в какой выборке, в каком архиве и у какого разметчика), а также списки `train.txt` и `val.txt`.

## Запуск

```
pip install -r requirements.txt
python video_to_dataset.py папка_с_видео out --every 1 --val 0.2 --batch 200 --labelers 4
```

Параметры: `--every` — шаг в секундах, `--near` — насколько похожие кадры выкидывать (0 — не выкидывать), `--start` и `--end` — отрезок видео в секундах, `--seed` — для воспроизводимого деления.

Пример вывода на трёх тестовых роликах, один из которых снят статичной камерой:

```
road.avi: взято кадров 5, оставлено 5, похожих отброшено 0
static.avi: взято кадров 5, оставлено 1, похожих отброшено 4
yard.avi: взято кадров 5, оставлено 5, похожих отброшено 0

Видео: 3. Кадров: 11 (похожих отброшено 4 из 15).
train: 6, val: 5 — деление по видео, без пересечений.
```

## Тесты

```
pip install pytest
pytest
```

Тест сам генерирует ролики и проверяет, что одинаковые кадры отбрасываются, видео не попадает в обе выборки, а все кадры доходят до архивов.
